## 3. 수행한 작업

1. **툴체인 제작** (`tools/`)
   - NFP 아카이브 파서, NFT 폰트 파서/라이터, SCRP 텍스트 추출/주입
2. **텍스트 추출** — 39,379개 문자열 (ARM9 1,044 + 시나리오 38,335)
3. **DeepSeek 번역** (`deepseek-chat`)
   - 그랜라간 **고유명사 용어집**을 시스템 프롬프트에 고정
   - 4단계: 줄 단위(9,010) → 초과분 축약(1,750) → 문자열 단위 재번역(1,261) → 압축(827)
   - `%s`/`%md` 등 포맷 지정자 보호
4. **한글 폰트 생성** — 굴림 11px 래스터라이즈, **1,028자** 신규 생성
5. **코드 재매핑** — 안 쓰는 한자 코드 2,359개 풀에서 배정 (CMAP/파일크기 무변경)
6. **롬 패치** — 동일 길이 덮어쓰기 (FAT/헤더 무변경)

### 검증
- 롬 크기/헤더/닌텐도 로고/보안영역 원본 동일
- 변경 영역이 폰트·ARM9 문자열 풀·SPC 스크립트에만 존재
- xdelta 왕복 복원 MD5 일치
- 패치 롬 내 무효 SJIS 시퀀스 0건

## 5. 남은 문제 (중요)

**ARM9 UI 문자열을 번역하면 게임이 `로드 파일 선택` 화면 진입에서 흰 화면으로 멈춥니다.**

- 이분 탐색 결과 **`0x11DBAC 'ロードファイル選択'`** 가 원인 문자열로 특정됨
  (전체 롬에서 유일한 1곳, 게임이 내부적으로 이름 조회/비교에 쓰는 것으로 추정)
- 현재는 ARM9 문자열 전체를 **원문 유지**해서 회피
- 대가: **메뉴/기술명/전투 텍스트는 일본어**, 스토리 대사는 한글

### 왜 해결이 어려운가
- ARM9 문자열이 단순 표시용이 아니라 엔진 내부 **키/룩업**으로 쓰이는 것으로 보임
- 개별 문자열을 하나씩 테스트해야 안전 여부를 알 수 있음 (1,044개)
