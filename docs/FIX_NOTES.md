# 프리징 원인 분석 및 해결 (2026-10-14)

## 결론 요약
| 증상 | 원인 | 해결 |
|---|---|---|
| ARM9 번역 시 로드 화면 흰 화면 정지 | UI 헤더 문자열 렌더 루틴이 **전각(2바이트) 전용**. 반각(ASCII 공백 포함) 1바이트라도 있으면 정지 | 원문에 ASCII가 없던 ARM9/SPC 문자열은 번역도 전각만 사용 (공백 = 0x8140, ASCII 기호 → 전각). `bspc.fw()` |
| SPC 번역 시 스토리 시작 후 검은 화면 정지 | **맵 이름 문자열이 키**로 쓰임. 각 SPC 파일 헤더(off 22)의 맵 이름(예: `ジーハ村通路Ａ`)과 다른 스크립트의 참조가 일치해야 함 | 맵 이름 41종(299곳)은 **번역하지 않고 일본어 유지** (`fixkeys.H`) |

## 근거 실험 (melonDS 1.1 + Xvfb 자동 구동)
- 원본/번역롬 모두 타이틀 → 로드 화면 → 슬롯01 → 플레이모드 → 스토리 → 맵 화면까지 자동 진행 가능 (tools/emu_harness)
- 0x11DBAC 한 문자열만 교체한 실험 (폰트 미패치 원본 롬 기준):
  - 일본어 동일/다른 문자열, 짧은 일본어 `ロード` → 정상
  - 한글 전각만(공백 0x8140 또는 공백 없음+전각 패딩) → 정상
  - `LOADFILE`(ASCII 공백 없음), `LOAD FILE`, 한글+ASCII `A` 1개 → **정지**
  - => 문자열 내용이 아니라 반각 문자 존재가 원인. (기존 이분탐색이 이 문자열만 잡은 건 로드 화면이 첫 번째로 표시되는 ARM9 헤더라서였고, 같은 종류의 다른 헤더도 위험)
- SPC: 파일 단위 이분탐색(422개) → `EV_005.SPC` → 문자열 단위 → idx 5966 (`ジーハ村通路Ａ` → `지하 마을`)
  - 같은 일본어가 `IWA_01~04`, `JIHA_01`, `EV_005`에 나오고, 헤더 7종이 전부 '지하 마을'로 번역돼 충돌도 있었으나, 충돌 제거(`지하통로Ａ` 등)만으로는 해결 안 됨 → **키 문자열은 일본어 유지가 확정 해결책**
- 반각→전각 변환만 적용한 SPC 전체 번역도 동일하게 멈춤 (반각은 SPC 정지 원인이 아님)

## 남은 과제
1. 맵 이름은 일본어로 표시됨 (번역하려면 이름이 쓰이는 모든 위치를 동시에 교체하거나 표시용 문자열을 따로 찾아야 함)
2. `NO DATA` → `NODATA`로 보임 (원인 미확인)
3. ARM9 문자열 2개는 슬롯이 짧아 번역 못 넣고 일본어 유지
4. 맵 이름 외 다른 키 문자열이 더 있을 수 있음 (이후 구간 테스트 필요)
5. 공백이 전각이라 간격이 넓음 → 폭 좁은 공백 글리프를 따로 배정하는 방법 검토 가능
